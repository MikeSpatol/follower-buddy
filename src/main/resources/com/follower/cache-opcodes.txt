# The cache definition formats LiveCacheParser reads, opcode by opcode: a
# port of runelite-cache's ItemLoader, KitLoader and SpotAnimLoader,
# transcribed from the library's bytecode and validated in game by diffing
# every entry against the offline dumper's output.
#
# A definition is a stream of opcodes, each followed by its own payload, ended
# by a zero. EVERY opcode must be consumed at its exact width or the stream
# desynchronises and the rest of the definition parses as garbage, so an
# opcode that is not listed here fails the definition instead of guessing.
#
# One line per opcode, or per run of opcodes with the same payload:
#   <type> <opcodes> <fields...>      opcodes: 4  or  3,9  or  30-39
# The fields are read in order:
#   b  byte (signed)          B  byte (unsigned)
#   h  unsigned short         i  int
#   s  string, ended by a zero byte
#   f  a flag: no payload, its presence is the value
#   c  find/replace pairs: a count byte, then that many (find short, replace short)
#   H  a count byte, then that many unsigned shorts
#   I  a count byte, then that many ints
#   L  an unsigned short count, then that many unsigned shorts
#   o  item menu sub-ops: a group byte, then (index byte, string) pairs ended by a zero index
#   p  params: a count byte, then that many (isString byte, 24-bit key, string or int)
# A field written kind=name keeps its value under that name; a bare field is
# read and skipped. When two opcodes write the same name, the later one in the
# stream wins, as in the loaders.
